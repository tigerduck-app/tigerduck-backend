# Phase 2: User-Scoped Data Snapshot + Cross-Device Sync — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement migration-plan Phase 2 — the 11 user-data tables plus the `/v3` sync, courses/assignments, settings, and bulletin-subscription/state APIs, with the security-review fixes for the changelog ordering race (1.1) and client clock skew (1.9).

**Architecture:** New `server/sync/` package (models, changelog service, merge helpers, routes). Builds on Phase 1's auth (`CurrentAuthDep`). All user-visible writes append to `user_change_log` inside the same transaction that locks the user's `user_sync_state` row — guaranteeing per-user commit-order == revision-order (review 1.1). Per-field merge clamps client timestamps to server now (review 1.9).

**Tech Stack:** Same as Phase 1. Tests follow the Phase-1 e2e pattern (login via StaticMoodleVerifier, Bearer-auth'd calls).

**Key invariants:**
- Changelog append = `UPDATE user_sync_state ... (row lock) → INSERT user_change_log → same txn commit`. Per-user writers serialize on the row lock, so a client paging `/v3/sync` can never permanently skip a revision.
- Client-supplied per-field timestamps are clamped to `min(client_ts, now())`; future timestamps cannot poison merge forever.
- Changelog payloads are routing hints only (entity ids / field names), never documents or HTML.
- Settings revision is server-incremented; `base_revision` mismatch → 409 with server state; create race on the partial unique index → 409.

### Task 4: Changelog service (review fix 1.1)
`server/sync/changelog.py`:
- `async def append_change(session, *, user_id, entity_type, entity_id, operation, payload=None, device_id=None) -> int` — upserts `user_sync_state` with `UPDATE ... SET current_revision` AFTER inserting the log row, but takes the row lock FIRST via `INSERT ... ON CONFLICT (user_id) DO UPDATE` pattern: lock user_sync_state row (insert-if-missing + SELECT FOR UPDATE), INSERT changelog RETURNING revision, UPDATE current_revision. All in caller's transaction.
- `async def read_changes(session, *, user_id, since_revision, limit)` → (changes, current_revision, has_more); raises `RevisionExpired` when `since_revision < compacted_revision`.
Tests: append assigns increasing revisions; concurrent appends for same user serialize (two parallel sessions — second blocks until first commits); read pagination; expiry. Commit `feat(Sync): add change log service with per-user commit ordering`.

### Task 5: Merge helpers (review fix 1.9)
`server/sync/merge.py`: `clamp_ts(client_ts, now)`; `apply_field(entity, field, value, client_ts, device_id, now)` — applies when `clamped_ts > stored_ts` (None counts as -inf), sets `<field>`, `<field>_updated_at = clamped`, `<field>_device_id`. Unit tests incl. future-timestamp clamp. Commit `feat(Sync): add per-field merge helpers with clock-skew clamping`.

### Task 6: Sync read APIs
`GET /v3/sync?since_revision=&limit=` (default/max limit 500; 410 + `min_available_revision` on expiry), `GET /v3/sync/full` (REPEATABLE READ txn snapshot of all user entities + current_revision). Commit `feat(Sync): add incremental and full sync endpoints`.

### Task 7: Initial upload
`POST /v3/sync/initial-upload`: body carries courses (snapshot), assignments (snapshot), course/assignment overrides, skipped dates, settings docs, bulletin subscriptions. Idempotent upserts on natural keys; everything appends changelog; single transaction. Commit `feat(Sync): add initial upload endpoint`.

### Task 8: Courses & assignments APIs

Skipped-dates: `PUT /v3/courses/{id}/skipped-dates/{date}` + `DELETE` (soft). Commit `feat(Academics): add course and assignment read and override endpoints`.

### Task 9: Settings documents
`GET /v3/settings/{namespace}`, `GET /v3/settings?namespaces=`, `PUT /v3/settings/{namespace}` with `base_revision` optimistic concurrency (409 + server doc on mismatch; create with `base_revision=null`; unique-violation race → 409). Changelog payload `{revision}` only. Commit `feat(Settings): add settings document sync with optimistic concurrency`.

### Task 10: Bulletin subscriptions + states

Commit `feat(Sync): add changelog retention with compacted revision tracking`.
